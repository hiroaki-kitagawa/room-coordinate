# room-coordinate ゲーム仕様書

## 1. 文書情報

- 文書名：room-coordinate ゲーム仕様書
- 対象：初期リリース（MVP）
- ステータス：初版
- 最終更新日：2026-08-17
- 備考：「暫定」と記載した数値・内容は、実装前の企画レビューで変更可能とする。

## 2. ゲーム概要

### 2.1 コンセプト

家具を手で掴むようにドラッグし、自分だけの部屋をつくる。

### 2.2 ジャンル

2Dルームコーディネートゲーム。

プレイヤーはサイドバーから家具を選び、見取り図形式の部屋キャンバスへドラッグ＆ドロップして配置する。家具は配置可能な位置へスナップし、必要な家具をそろえると部屋を確定できる。

### 2.3 体験の柱

1. **直接操作**：座標を入力せず、家具を掴んで動かす。
2. **即時プレビュー**：ドラッグに合わせてゴーストと部屋の状態が変化する。
3. **明快な可否表示**：置ける場所と置けない場所を色・枠・カーソルで判別できる。
4. **完成の達成感**：条件を満たすと「確定」が有効になり、完成画面へ進める。

## 3. 対象範囲

### 3.1 MVPに含めるもの

- 1つの部屋での家具配置
- サイドバーからの家具追加
- 配置済み家具の再移動
- ドラッグ中のゴースト表示
- グリッドまたは定義済み配置点へのスナップ
- 配置可否のリアルタイム判定と視覚表示
- 必須条件の進捗表示
- 条件達成による確定ボタンの有効化
- 配置のリセット
- 完成画面
- マウス操作とタッチ／ペン操作

### 3.2 MVPに含めないもの

- 家具の自由回転、拡大・縮小
- 部屋形状や床・壁紙の編集
- 複数部屋、階層、オンライン共有
- ユーザーアカウント、クラウド保存
- スコア、時間制限、対戦要素
- 座標の数値入力を用いた配置

## 4. 世界観・アート方針

- トーン：やわらかい、自分の部屋、すっきり、安心感
- 配色：ベージュ、アイボリー、薄い木目を基調とし、家具は低彩度のパステルカラーとする。
- 形状：角を丸め、枠線や影は強くしすぎない。
- 動き：短くやわらかなイージングを使い、配置時には軽く吸い付くようなスナップ感を出す。
- レイアウト：余白を十分に取り、家具や操作要素を詰め込みすぎない。
- 参考とする雰囲気は『あつまれ どうぶつの森』の親しみやすさとする。ただし、既存作品の固有デザイン、素材、UI、キャラクターを複製しない。

## 5. 対応環境と入力方式

- 対象：デスクトップおよびタブレット向けWebブラウザを想定する。
- 主操作：マウス、タッチ、ペンによるドラッグ＆ドロップ。
- キーボード操作：アクセシビリティ対応として提供する。家具選択後、方向キーで候補位置を移動し、EnterまたはSpaceで配置できるものとする。
- 画面幅が狭い場合、サイドバーは横スクロール可能な家具トレイへ変形してよい。

## 6. 画面構成

### 6.1 コーディネート画面

#### サイドバー

- ドラッグ可能な家具アイコンを一覧表示する。
- 各項目には家具画像と名称を表示する。
- 家具が必須条件の対象である場合は、そのことが分かる印を付ける。
- 同じ家具を複数配置できる場合、サイドバーの元アイコンは配置後も残す。
- 配置上限に達した家具は無効表示にし、追加できない理由を示す。

#### 部屋キャンバス

- 部屋の床領域、壁、出入口などの禁止領域を見取り図として表示する。
- 配置可能範囲と配置禁止範囲を視覚的に区別する。
- 配置済み家具を表示し、再度ドラッグして移動できるようにする。
- ドラッグ中はスナップ先と配置可否をリアルタイムに表示する。

#### フッター

- 必須条件の進捗を表示する。
- 「確定」ボタンを表示する。条件未達時は `disabled` とし、見た目と操作の両方で無効にする。
- 「リセット」ボタンを表示する。

### 6.2 完成画面

- 完成した部屋全体を、操作UIを抑えた状態で表示する。
- 完成を伝える短いメッセージを表示する。
- 「部屋を編集する」ボタンで、配置状態を維持したままコーディネート画面へ戻れる。
- 「最初から」ボタンで、確認後に初期状態へ戻れる。

## 7. 基本プレイフロー

1. コーディネート画面を開く。
2. サイドバーから家具を選択し、ドラッグを開始する。
3. 家具のゴーストを部屋キャンバス上で移動する。
4. 配置可能な候補位置にゴーストがスナップする。
5. 配置可能な場所でドロップすると家具が配置される。
6. 必要に応じて複数の家具を配置・再配置する。
7. 必須条件をすべて満たすと「確定」ボタンが有効になる。
8. 「確定」を押すと完成画面へ遷移する。

## 8. 家具仕様

各家具は少なくとも次の情報を持つ。

| 項目 | 内容 |
| --- | --- |
| 家具ID | 家具種別を一意に識別する値 |
| 名称 | 画面表示用の名称 |
| アイコン／画像 | サイドバーとキャンバスで使う表示素材 |
| 占有サイズ | 横・縦に占有するマス数 |
| 配置可能カテゴリ | 床、壁際などの配置ルール |
| 配置上限 | 部屋へ置ける最大個数 |
| 必須条件タグ | 完成条件の判定に用いる分類 |
| 基準点 | スナップおよび当たり判定に使う位置 |

### 8.1 初期家具セット（暫定）

| 家具 | 占有サイズ（暫定） | 上限（暫定） | 必須 |
| --- | ---: | ---: | --- |
| ベッド | 2 × 3 | 1 | はい |
| テーブル | 2 × 2 | 1 | はい |
| チェア | 1 × 1 | 4 | いいえ |
| ソファ | 3 × 1 | 1 | いいえ |
| 観葉植物 | 1 × 1 | 3 | いいえ |
| ラグ | 4 × 2 | 1 | いいえ |

### 8.2 ラグの重なりルール

- ラグは床レイヤーとして扱い、通常家具より常に背面へ表示する。
- テーブル、チェア、ソファ、ベッド、観葉植物はラグと重ねて配置できる。
- ラグ同士、およびラグ以外の家具同士は重ねて配置できない。
- ラグの上に家具がある状態でラグを移動しても、家具の位置は変更しない。

## 9. ドラッグ＆ドロップ仕様

### 9.1 ドラッグ開始

- 家具アイコンまたは配置済み家具を押下し、移動開始と判定された時点でドラッグ状態へ移る。
- ドラッグ可能な要素ではカーソルを `grab`、ドラッグ中は `grabbing` 相当にする。
- 誤操作防止のため、短い移動距離を超えるまではクリック／タップとして扱ってよい。

### 9.2 ドラッグ中

- ポインターに追従する家具ゴーストを必ず表示する。
- ゴーストは実体と区別できる半透明表示とする。
- ゴーストの基準点は、ドラッグ開始時に掴んだ位置との関係を保つ。
- 部屋内では最寄りの有効なグリッドまたは配置点へスナップする。
- 現在位置の判定結果を毎回更新する。
- 画面端へ近づいた際に必要であればキャンバスを自動スクロールする。

### 9.3 ドロップ成功

- 家具全体が配置可能範囲内にある。
- 他の家具の占有領域と重なっていない。
- 出入口などの禁止領域を塞いでいない。
- 家具固有の配置条件を満たしている。
- 上記をすべて満たす位置でドロップすると、スナップ先へ家具を配置する。
- 配置時は短いスナップアニメーションを再生し、必須条件の進捗を即座に更新する。

### 9.4 ドロップ失敗

- 不可位置でドロップした場合、新規家具はサイドバーへ戻し、配置済み家具はドラッグ開始前の位置へ戻す。
- 戻る動きはアニメーションで示す。
- 同時に、簡潔で具体的な理由を表示する。

理由メッセージ例：

- 「部屋の中に置いてください」
- 「ほかの家具と重なっています」
- 「ドアの前には置けません」
- 「この家具はこれ以上置けません」

## 10. 配置可能判定と視覚ルール

### 10.1 判定優先順位

複数の違反がある場合、プレイヤーが直しやすいよう、次の優先順位で1つの主理由を表示する。

1. 部屋の範囲外
2. 禁止領域との重なり
3. 家具同士の重なり
4. 家具固有条件の不一致
5. 配置上限超過

### 10.2 表示状態

| 状態 | ゴースト | 候補マス／領域 | 補助表示 |
| --- | --- | --- | --- |
| 配置可能 | 通常色または淡い緑の輪郭 | 淡い緑の塗りと実線枠 | 必要に応じてチェック表示 |
| 配置不可 | 淡い赤または赤い輪郭 | 淡い赤の塗りと破線枠 | 禁止記号と理由メッセージ |
| キャンバス外 | 低彩度・半透明 | なし | 「部屋の中に置いてください」 |
| 未操作 | 表示なし | 配置可能範囲と禁止領域を弱く常時表示 | 凡例を表示可能 |

- 色だけに依存せず、実線／破線、記号、文言を併用する。
- 可否表示はドラッグ中に強調し、通常時は部屋の見た目を妨げない強さにする。

## 11. スナップ仕様

- 家具の位置はグリッド単位またはあらかじめ定義した配置点にそろえる。
- 初期仕様では正方形グリッドを採用する（マス寸法は画面サイズに応じて拡縮可能）。
- 判定はスナップ後の占有マスに対して行う。
- ゴーストはポインター位置に最も近い候補へ移動する。
- 同距離の候補がある場合は、直前の移動方向を優先し、表示の揺れを防ぐ。
- 配置済み家具を掴んだ直後は元位置を有効な候補として保持する。

## 12. 完成条件

### 12.1 MVPの必須条件（暫定）

- ベッドを1個配置している。
- テーブルを1個配置している。
- すべての配置済み家具が有効な位置にある。

### 12.2 確定ボタンの状態

- 条件未達：`disabled`。フォーカスやクリックで確定処理が実行されない。
- 条件達成：有効。視覚的にも主操作であることを明確にする。
- 条件未達時は、ボタン付近に「ベッドを置こう」など残り条件を表示する。
- 家具移動により条件が再び未達になった場合、即座に無効へ戻す。

## 13. リセット仕様

- 「リセット」を押すと確認ダイアログを表示する。
- 確認後、すべての配置家具を削除し、初期状態へ戻す。
- キャンセルした場合は何も変更しない。
- リセット後は完成条件と確定ボタンの状態も再評価する。

## 14. 状態設計

ゲームは少なくとも次の状態を持つ。

| 状態 | 説明 |
| --- | --- |
| 初期状態 | 家具未配置。確定不可 |
| 通常状態 | 家具の選択、追加、再移動が可能 |
| ドラッグ中・配置可能 | 有効候補をプレビュー中 |
| ドラッグ中・配置不可 | 無効候補と理由を表示中 |
| 条件達成 | 確定可能 |
| リセット確認中 | 配置操作を一時停止 |
| 完成状態 | 完成画面を表示 |

- 一度にドラッグできる家具は1つだけとする。
- ドラッグ中に画面外へポインターが出た場合も、終了イベントを捕捉して状態を復帰させる。
- ウィンドウのフォーカス喪失や入力キャンセル時は、失敗ドロップと同様に元へ戻す。

## 15. フィードバックとアニメーション

- 家具を掴む：少し持ち上がるような影と拡大（目安 100〜150ms）。
- スナップ候補変更：やわらかな位置補間（目安 80〜120ms）。
- 配置成功：小さなバウンスまたは沈み込み（目安 150〜220ms）。
- 配置失敗：元位置へ戻る移動（目安 180〜250ms）と理由表示。
- 条件達成：進捗表示と確定ボタンを穏やかに強調する。
- `prefers-reduced-motion` が有効な環境では、移動を伴う装飾アニメーションを抑制する。

## 16. サウンド（任意機能）

MVPでは必須としない。導入する場合は、掴む、配置成功、配置失敗、条件達成に短く柔らかな効果音を割り当て、ミュート設定を提供する。

## 17. アクセシビリティ

- 可否を色だけで伝えず、枠線、アイコン、テキストを併用する。
- テキストと背景は十分なコントラストを確保する。
- 操作対象には認識可能な名称を付与する。
- キーボードだけでも家具の追加、移動、配置、確定、リセットができるようにする。
- 状態変化と配置失敗理由は支援技術へ通知する。
- タッチ対象は誤操作しにくい大きさと間隔を確保する。

## 18. データ保持

- MVPではプレイ中の状態をメモリ上に保持する。
- ページ再読み込み後の復元は必須としない。
- 将来の保存機能に備え、配置情報は家具ID、個体ID、グリッド座標、向き（将来用）で表現できる構造とする。

## 19. エラー・例外時の挙動

- 家具画像を読み込めない場合は、名称入りの代替表示を使い、操作を継続できるようにする。
- キャンバスサイズが変化した場合、論理グリッド座標を維持して再描画する。
- 配置データが不正な場合は該当家具を配置せず、ゲーム全体が操作不能にならないようにする。
- 同一入力による二重配置を防止する。

## 20. 受け入れ基準

### 20.1 基本操作

- サイドバーの全家具をドラッグ開始できる。
- ドラッグ中、家具のゴーストがポインターへ追従する。
- 配置可能位置でドロップすると、家具がスナップして残る。
- 配置不可位置でドロップすると、新規家具は追加されず、移動家具は元位置へ戻る。
- 配置失敗時に理由が確認できる。
- 配置済み家具を再度ドラッグして移動できる。

### 20.2 視覚表現

- 配置可能と配置不可が色、枠、記号または文言の組み合わせで判別できる。
- 禁止領域が通常時にも認識できる。
- ドラッグ中の家具と配置済み家具を区別できる。
- スナップ後の家具がグリッドに整列している。

### 20.3 条件と遷移

- 必須家具が不足している間、確定ボタンを実行できない。
- 残りの必須条件が画面上で分かる。
- 必須条件を満たすと確定ボタンが即座に有効になる。
- 確定すると、現在の配置を反映した完成画面が表示される。
- 完成画面から編集へ戻った際、配置が維持される。
- リセット確認を承認すると全家具が取り除かれる。

### 20.4 入力と堅牢性

- マウスとタッチの両方で主要フローを完了できる。
- ドラッグをキャンセルしても家具が消失・複製されない。
- 画面サイズ変更後も家具の論理位置が維持される。

## 21. 今後決定する項目

- 部屋の具体的な形状、グリッド数、ドア・窓など禁止領域の位置
- 家具画像、各家具の占有サイズと配置上限
- 必須家具と完成条件の最終内容
- 対応ブラウザと最小画面サイズ
- 配置履歴のUndo／RedoをMVPへ含めるか
- 家具削除の操作方法
- 自動保存および共有機能の優先度
- 効果音の採用可否
